# H200 K96 COCO seed521, single request

This request runs only downstream seed521. The ImageNet-1K seed501 checkpoint
is fixed at 100 epochs and verified by SHA256 before model construction.
The other two downstream seeds remain on qlab.

Entrypoint: `bash h200/run_k96_coco_521.sh` from a clean checkout of the
approved commit. Request **7 MIG units (one full H200)**, Python, and
`pytorch/pytorch:latest`. The launcher rejects an 18GB MIG slice before
installing dependencies or downloading COCO.

The same request downloads/verifies COCO into its own `/app/output` tree,
performs a bounded two-update full-input and save/restore gate, then runs
Mask R-CNN/FPN for 12 epochs with physical batch2, effective batch16,
BF16, AdamW 1e-4/0.05, warmup1000, and drops at epochs8 and11.
It evaluates the complete COCO val2017 set at the end. Two spawned data
workers with prefetch factor one match the qlab execution profile while
preserving the scientific batch, head, and augmentation recipe. A lightweight
heartbeat is written every five optimizer updates; full checkpoints remain
every 200 updates.

The control path `/k96coco` is isolated from the completed IN-1K-10% session.
The H200 process creates its own short-lived agent token and enrolls only from
the platform's allowed egress IP. No token or password is placed in GitHub
code or the public request. An owner-side observer saves live log events and
records W&B in `daehwa/alphabet2d-dense-transfer`; the owner command can send
a stop request without changing GitHub. A stop requests a cooperative
checkpoint. New requests still have job-scoped `/app/output` mounts, so an
old request's checkpoint may not be visible after resource release.

The ImageNet checkpoint is transferred privately through the authenticated
relay before submission. The agent fetches it using its short-lived session
and verifies SHA256
`a72b70a422dc96d06c0cd88bf29a822793af40c65c67858d48f1467f6503e752`.
No public release is required.
No GitHub issue is submitted by these scripts.
